# GJY 编辑器 v1.0.3

GJY 编辑器是一个基于 Tkinter 的桌面 GUI 工具，用于在本地创建、查看、编辑和管理自定义的 .gjy / .gjyx 文件。支持三种文件类型：文本（text）、图片（image）和 A4 混合布局（a4），其中 A4 模式可以将文本与图片元素拖拽、缩放并排版到页面上。

---

## 主要特性

- 配置管理：保存/加载 gjy_config.json（默认存储目录）。
- 文件浏览：列出当前目录下的 .gjy / .gjyx 文件，支持刷新、删除与打开存储位置提示。
- 文本文件（text）：在内置文本框中输入内容，保存时使用 Base64 编码。
- 图片文件（image）：选择本地图片，保存为 Base64 编码嵌入 .gjy 文件，查看时可解码显示。
- A4 混合（a4）：拖拽式 A4 画布，支持添加文本元素与图片元素；图片支持选中并用鼠标滚轮缩放；保存时将元素列表以 JSON 形式写入文件头（包含图片 base64）。
- 查看窗口：显示文件元信息（类型、版本、创建/修改时间）并预览内��或页面排版。

## 运行要求

- Python 3.7+
- tkinter（通常随 Python 安装）
- Pillow（PIL）库：用于图像打开与处理

安装 Pillow：
```bash
pip install pillow
```

启动项目：
```bash
python gjy_file_edit_v103.py
```
（需在带图形界面的环境中运行）

## 文件存储位置

默认会在用户主目录下创建 `GJY_Files` 文件夹保存 .gjy 文件。可在程序界面更改当前存储目录，并将其设为默认。

## GJY 文件格式（约定）

程序采用基于注释头与 Base64/JSON 的自定义格式，示例如下：

- 文件头（注释）包含元信息（必须/可选）：
  - `#GJY`（标识）
  - `#v...`（版本，例如 `#v1.0.3`）
  - `#Type: <text|image|a4>`
  - `#Created: YYYY-MM-DD HH:MM:SS`
  - `#Modified: YYYY-MM-DD HH:MM:SS`

- 文本或图片类型：
  - 注释头之后的第一条非注释行被视为编码内容（Base64）。
  - text：Base64 解码为 UTF-8 文本。
  - image：Base64 解码为二进制图片数据。

- A4 混合类型：
  - 在头部使用单行保存元素 JSON：
    - `#A4_ELEMENTS: <JSON>`
  - 每个元素示例（JSON）：
    - 文本元素：
      `{ "type":"text", "content":"示例文字", "x":100, "y":150 }`
    - 图片元素：
      `{ "type":"image", "image_data":"<base64>", "original_path":"...","width":120,"height":80,"x":200,"y":220 }`

注意：当前实现把 A4 元素 JSON 写在单行注释中；若图片 base64 很大，行会很长。

## 使用说明（快速指南）

1. 启动程序后，程序会显示当前存储目录的文件列表。
2. 在“创建GJY文件”处选择文件类型（文本/图片/A4混合）。
3. 文本：输入文件名与文本内容，点击“新建文件”或“保存修改”。
4. 图片：选择图片文件，预览后保存（注意：编辑图片类型时需重新选择图片以替换）。
5. A4 混合：
   - 点击“添加文本”输入文本并添加到画布。
   - 点击“添加图片”选择图片并添加到画布（自动缩放限制）。
   - 在画布上点击元素选择：文本会变红，图片会出现红色选择框。
   - 拖动选中元素更改位置；对选中图片使用鼠标滚轮缩放。
   - 点击“删除选中”移除元素。
   - 保存时会把页面元素以 JSON 写入文件头。

6. 在文件列表中选择文件后可点击“查看”以打开查看窗口，预览内容和元信息；双击列表项也会打开查看窗口。

## 已知限制与注意事项

- parse/保存逻辑：
  - 程序在解析时只读取注释头后第一条非注释行为编码内容；多行 Base64 或其它布局可能导致解析失败。A4 元素依赖单行 JSON。
- 图片还原：
  - 对于 image 类型的文件，编辑时不会自动还原为临时图片文件，需要用户重新选择图片。
- A4 图片缩放：
  - 缩放实现尝试通过原始路径打开图片（来自 element['content']），如果原路径不存在则可能失败。加载 A4 时图片数据以 base64 保存，但缩放逻辑并不总是使用内存中的图像 bytes。
- 错误处理：
  - 代码中存在若干处捕获异常后静默（except: pass），不利于调试与定位问题。
- 性能/可用性：
  - 将大量图片 base64 写入单行会使文件变大且可读性差；UI 功能（撤销/重做、属性编辑、层级管理）尚未实现。

## 改进建议（可选实现）

- 改进解析器：支持多行编码体与更健壮的头部解析。
- A4 图片元素：保存并使用内存图片 bytes（避免依赖原始文件路径），缩放时优先使用内存数据。
- 更好的错误报告：日志文件或在 UI 中显示详细错误。
- UI 增强：撤销/重做、元素属性面板（字体/颜色/大小）、元素对齐与分层管理。
- 将 A4 元素的 JSON 分块存储（多行或独立段）以提升可读性与稳定性。
